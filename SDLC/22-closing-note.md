# Closing note

This document describes a process that does not exist yet. It will be wrong in places — some rules will turn out to be overhead, some will turn out to be missing, and some will be right for a team of four and wrong for a team of ten.

That is expected. **The process is a product, and the team is its user.** Treat friction as a bug report, use the retrospective as the intake channel, and change this document by pull request when it stops fitting.

The measure of success is not compliance with this document. It is that work is visible, changes are reviewed, releases are boring, and problems are found by us before they are found by our users.

**Start with §16 Phase 1. Do not start with everything.**
